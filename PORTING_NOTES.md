# Заметки по порту Forge 1.20.1

## Цель

Этот проект является отдельным бэкпортом NeoForge 1.21.1-версии Craft & Find. Цель — сохранить внешний вид, игровой процесс, значения конфигов и накопленные исправления, меняя только код, несовместимый с Minecraft/Forge 1.20.1.

## Замены платформенного API

- Регистрация блоков и предметов перенесена на Forge `DeferredRegister`/`RegistryObject`.
- Точка входа использует `FMLJavaModLoadingContext` и Forge event bus.
- Конфиги перенесены на `ForgeConfigSpec` и `ModLoadingContext`.
- Сеть перенесена с payload API NeoForge на Forge `SimpleChannel`.
- Четыре сообщения используют `FriendlyByteBuf`: снимок хранилища, запрос подсветки, позиции подсветки и ghost-рецепт.
- Клиентский рендер подключён к `RenderLevelStageEvent` и `RenderGuiEvent.Post`.
- Рецепты и достижения приведены к формату data pack Minecraft 1.20.1.
- Код компилируется с целевой версией Java 17.

## Сохранённая архитектура

- `StorageWorkbenchMenu` остаётся наследником ванильного `CraftingMenu`.
- Реальные предметы извлекаются сервером из настоящих контейнеров; клиент не считается доверенным источником.
- Персональная сетка крафта хранится по игроку, измерению и координатам главной части верстака.
- Полный поиск блоков выполняется редко, снимок содержимого — чаще; одинаковые снимки повторно не отправляются.
- Двойные сундуки группируются до подсчёта и визуализации.
- Предмет маркера рендерится в GUI-проходе с проекцией мировой точки, как в финальной версии 1.21.1.

## Что требует проверки в игре

Статическая проверка не заменяет запуск Minecraft. Наиболее чувствительные места:

1. Инъекции Mixin в книгу рецептов и расположение её кнопок.
2. Перемещение финальных координат ванильных слотов через accessor-mixin.
3. Проекция и прозрачность рамки/3D-предмета при движении камеры и за стеной.
4. Синхронизация личной сетки крафта на выделенном сервере.
5. Автоматическое размещение рецепта с материалами одновременно у игрока и в хранилищах.

Полная последовательность проверок находится в `TEST_CHECKLIST.md`.

## Текущее ограничение интеграций

Порт сохраняет исходное поведение и сканирует ванильный `Container`. Forge-capability `IItemHandler` намеренно не добавлялся в рамках бэкпорта, чтобы не менять семантику и не смешивать порт с новой функцией.
